# 按项目触发的补充问题

以下问题仅在影响当前任务且尚无答案时询问；项目已有约定或用户已回答的内容直接沿用，不逐项重复询问。

本表不是完整的提问边界。在开发或构建的任何环节，出现需求模糊或尚未确定的多种可行实现路径时，都应及时说明选项和差异，由用户选择；答复前暂停依赖该选择的实现，可继续独立工作。

这些内容取决于软件类型，建议在出现相应需求时再确认，不为所有 WPF 工具统一预设复杂方案。

| 触发场景 | 应询问的内容 | 建议方向 |
| --- | --- | --- |
| 配置、文件导入导出、自动保存 | 保存位置、文件格式、版本兼容、覆盖与失败恢复策略 | 明确用户数据与临时文件边界，重要保存避免留下半写入文件 |
| 数据库或网络请求 | 超时、取消、重试、事务、离线行为、认证与凭据保存 | 重试前确认幂等性，不对所有失败机械重试 |
| 删除、批量覆盖等不可逆操作 | 是否需要确认、备份、撤销或回收站 | 依据后果设计操作流程，验证使用独立测试数据 |
| 大量数据或长时间任务 | 预计规模、性能目标、进度与取消、关闭窗口时如何处理 | 先满足明确规模和响应性要求，再根据测量优化 |
| 多语言或跨区域使用 | 支持的语言、日期／数字格式、时区 | 区分展示格式与稳定的数据交换格式 |
| 金额、测量或科学计算 | 数值范围、单位、精度、舍入和误差要求 | 根据业务选择数值类型，不统一套用 `double` 或 `decimal` |
| 自定义主题或商用 UI 组件 | 主题切换、无障碍要求、许可证与预算 | 保留 Windows 原生默认值；额外设计按实际需求采用 |
| 打包、发布、安装与更新 | 支持的 Windows 版本和架构、部署方式、运行时、签名及更新渠道 | 在发布前明确部署约束，不由开发框架默认值推断 |
