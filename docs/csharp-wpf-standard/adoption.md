# 项目接入、配置与统一迁移

本文件与 `code-standard.md`、`project-scenarios.md` 一同落地到项目的 `docs/csharp-wpf-standard/`。安装规范资料和完成代码迁移是两个独立的状态。

## 接入后的文件

| 项目路径 | 用途 |
| --- | --- |
| `docs/csharp-wpf-standard/code-standard.md` | 项目采用的完整规范快照 |
| `docs/csharp-wpf-standard/project-scenarios.md` | 按实际需求询问的数据、网络、部署等问题 |
| `docs/csharp-wpf-standard/adoption.md` | 本说明 |
| `docs/csharp-wpf-standard/editorconfig.template` | 可供审查和合并的格式配置模板 |
| `docs/csharp-wpf-standard/skill-state.json` | 接入脚本管理的版本和校验信息，不代表迁移完成 |
| `AGENTS.md` 的专属标记区块 | 引导 AI 读取项目内规范，保留其他内容 |
| `.editorconfig` | 条件满足时新建；已有文件及继承配置不强制覆盖 |

## 首次接入流程

1. 确定项目范围，阅读已有指令、工作区修改和仓库配置。以任务指定的解决方案或项目目录为根；共享仓库有其他语言时，不把该规范扩展到整个仓库的无关文件。
   保留用户未提交改动，不通过 `reset`、`clean`、`stash` 或强制覆盖来清理工作区。对改名和格式调整也应区分用户已有修改与本次工作。
2. 检查根、祖先和子目录的 `.editorconfig`，以及适用的 `.gitattributes`。重点确认 BOM、换行、命名和格式化工具；不执行 Git 的全库行尾重写命令。
3. 运行接入脚本预览。脚本在明确的现有目录内写入固定的文档位置，保留已有文件；修正冲突后再 `-Apply`。用户已经要求接入或按此 skill 开发时不重复询问这些本地写入。
4. 检查实际复制结果和 `AGENTS.md` 区块。检查编辑器配置是否创建、保留或待合并，不能把“复制了模板”表述成“模板已生效”。
5. 对已有代码说明统一迁移是否在本次任务范围。仅复制资料时标明代码尚未统一迁移；用户已要求全库迁移时接着完成，不再次索取相同授权。

## EditorConfig 的应用边界

- 新项目且没有已生效的编码／行尾约定时，模板可成为根 `.editorconfig`。模板只针对 C#/XAML，且不设置 `root = true`。
- 已有配置时逐项合并，保留 BOM 和行尾等规范允许的项目差异；先检查更具体的子目录规则，避免只改根配置却声称全项目生效。
- 字段、私有属性、常量和接口命名规则只提供编辑器建议；现有更具体的规则可能覆盖它们。常量优先于普通私有字段，检查实际诊断后再执行改名。
- 模板不启用第三方分析器，不安装包，不将全部警告升级为错误。
- 模板不自动清理所有行尾空格，因为 C# 原始字符串和 XAML 文本中的空格可能是数据。对无意义尾随空白按语法及实际内容清理，这是实现正文空白规则的方式，不是允许任意尾随空白。
- UTF-8、CRLF、缩进等会影响编辑器保存行为，也要检查多行字符串和文本资源。不得对源文件做不区分语义的全文替换。
- 全量 XML 注释、单行签名和调用、复杂参数结构例外、XAML 根标签换行、`Async` 语义及有意义的命名仍需 AI／人工检查。不要承诺某个通用格式化命令能全部满足。

## 统一迁移清单

- 确定人工维护的文件范围，排除 `bin`、`obj`、生成代码和第三方代码；不要仅凭文件名判断所有 `.Designer.cs` 等文件都能改。
- 记录已有构建或测试失败；迁移代码风格，不默认升级目标框架、启用新的架构或引入依赖。
- 按规范统一排版、命名与注释。处理改名时检查绑定路径、`x:Name` 引用、反射、序列化、持久化格式及外部接口。
- 影响公开契约的改名归为实质性调整，按任务约定渐进处理；不能用“风格迁移”掩盖行为变化。
- 检查构建、相关界面和风险所需的测试，如实说明未验证部分。迁移过程中若有功能修改，保持差异便于审查。
- 只有确实完成范围内的迁移并验证后，才在交付中声明完成；脚本从不自动给迁移打完成标记。

## 版本升级与项目定制

- skill 包是规范的发行源，项目内文档是固定版本快照。更新本机 skill 不会自动改写所有项目。
- 默认重复接入应保持同一结果。升级规范时使用 `-Update`，由脚本检查校验信息及修改冲突。
- 自定义项目规则优先放在独立的项目说明或 `AGENTS.md` 管理区块之外，注明适用范围和理由；避免直接编辑接入脚本管理的快照。
- 管理文件或区块被人工编辑时，不强制覆盖。比较修改并保留项目意图后，再决定将定制移出管理区域或保留项目版本。
- 不删除版本记录以绕开更新保护，不将项目快照自动复制回原 skill。团队希望采用的规则修改，应编辑 skill 源版本并通过正常升级发布。
