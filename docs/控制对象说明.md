# FishBot C# Agent 控制对象说明

版本：1.0（2026-10-30）
适用：`xrce_csharp_agent`（纯 C# XRCE-DDS agent）

## 1. 结论

本程序**不按 ROS 节点名控制**，而是直接与主控板上的 **micro-ROS 固件节点** 通过 XRCE-DDS 通信。

主控板上的固件节点名（抓包确认）：

```text
fishbot_motion_control
```

对应 XRCE participant：

```text
0x0001
```

程序控制的是这个固件节点暴露的 **topic / publisher / subscriber / datawriter / datareader** 实体。

## 2. 控制对象总览

| 方向 | ROS2 话题 | 消息类型 | XRCE 实体 | 程序行为 |
|---|---|---|---|---|
| 下发控制 | `/cmd_vel` | `geometry_msgs/Twist` | DataReader `0x0006` | 发送 DATA，驱动电机 |
| 读取反馈 | `/odom` | `nav_msgs/Odometry` | DataWriter `0x0005` | 解析 x / y / yaw |
| 读取反馈 | `/imu` | `sensor_msgs/Imu` | DataWriter `0x0015` | 接收但不解析 |
| 服务（未使用） | `/fishbot_config` | `fishbot_interfaces/srv/FishBotConfig` | 服务端点 `0x0008` | 只学习，不调用 |

## 3. 实体关系树

```text
Participant 0x0001  fishbot_motion_control
├─ Topic 0x0022  rt/cmd_vel
│  └─ Subscriber 0x0004
│     └─ DataReader 0x0006   ← 程序往这里写 Twist
├─ Topic 0x0002  rt/odom
│  └─ Publisher 0x0003
│     └─ DataWriter 0x0005   → 程序读 x / y / yaw
├─ Topic 0x0012  rt/imu
│  └─ Publisher 0x0013
│     └─ DataWriter 0x0015   → 程序只记录，不解析
└─ Service 0x0008  /fishbot_config（程序未使用）
```

## 4. 控制流程

1. 程序向 `DataReader 0x0006` 发送 `DATA` 子消息。
2. payload 是 48 字节的 `geometry_msgs/Twist` CDR：
   - `linear.x / y / z`
   - `angular.x / y / z`
3. 主控板固件收到后，把线速度 / 角速度转换为左右轮目标速度。
4. 主控板内部 PID 驱动电机。
5. 固件通过 `DataWriter 0x0005` 上报 odom。
6. 程序解析 odom 的 `x / y / yaw`，用于 `forward` / `turn` 闭环。
7. 固件通过 `DataWriter 0x0015` 上报 imu；程序只接收，不参与控制。

## 5. 程序不控制的对象

| 对象 | 说明 |
|---|---|
| Nav2 / SLAM / RViz | 这些是上位机上的 ROS2 节点，不在小车主控板上；本程序没有实现它们 |
| 电机 / 编码器节点 | 不是独立 ROS 节点，由 `fishbot_motion_control` 固件直接管理 |
| `/fishbot_config` 服务 | 程序只识别端点，不发送配置请求；WiFi 等参数请用 `fishbot_tool.exe` 配置 |
| 雷达节点 | 当前没有雷达，也没有雷达驱动 |
| 避障 / 地图 | 没有雷达，程序不做避障和地图定位 |

## 6. 对象 ID 的依赖

这些对象 ID 是抓包确认的 **FishBot 固件固定分配**：

| 对象 | ID |
|---|---|
| Participant | `0x0001` |
| Topic cmd_vel | `0x0022` |
| Subscriber | `0x0004` |
| DataReader cmd_vel | `0x0006` |
| Topic odom | `0x0002` |
| Publisher odom | `0x0003` |
| DataWriter odom | `0x0005` |
| Topic imu | `0x0012` |
| Publisher imu | `0x0013` |
| DataWriter imu | `0x0015` |
| Service | `0x0008` |

如果更换固件版本或重新编译时改了实体编号，需要同步更新
`Xrce/Agent.cs` 中的 `DEFAULT_FISHBOT_OBJECTS`。

程序在收到真实 `CREATE` 报文时也会自动学习实体，并覆盖默认表。

## 7. 如何验证当前控制对象

### 7.1 查询状态

```powershell
cd "C:\Users\kw188\Desktop\ros小车\xrce_csharp_agent"
dotnet run -c Release -- --status
```

正常连接时：

```json
{
  "ok": true,
  "state": "idle",
  "pose": {"x": 0.0, "y": 0.0, "yaw": 0.0},
  "odom_age_ms": 35,
  "speed": {"linear": 0.05, "angular": 0.3},
  "sessions": 1,
  "active": 1,
  "cmd_vel_reader": true
}
```

关键字段：

| 字段 | 期望 | 含义 |
|---|---|---|
| `sessions` | ≥ 1 | 至少一个主控板会话 |
| `active` | ≥ 1 | 5 秒内有数据 |
| `cmd_vel_reader` | true | 找到 cmd_vel 的 DataReader |
| `odom_age_ms` | 0 ~ 200 | odom 正在更新 |

### 7.2 查看实时日志

agent 启动后会打印：

```text
RX ... subs=[CREATE]  kind=0x02 topic=odom
RX ... subs=[CREATE]  kind=0x05 topic=odom
RX ... subs=[CREATE]  kind=0x02 topic=cmd_vel
RX ... subs=[CREATE]  kind=0x06 topic=cmd_vel
RX ... subs=[WRITE_DATA] topic=odom
    odom x=... y=... yaw=...
```

看到 `topic=cmd_vel` 的 DataReader 和实时 `odom`，说明控制对象已就绪。
